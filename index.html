Diagnóstico rápido

⚠️ Sempre verificar logs antes de reiniciar qualquer serviço em produção. Ambiente CCT1 e CCT2 possuem janelas de manutenção distintas.

// verificar status do Apache

bash 
# status do serviço
systemctl status httpd

# testar configuração antes de reload
apachectl configtest

# reload sem derrubar conexões
apachectl graceful

# tail dos logs de erro
tail -f /var/log/httpd/error_log

// verificar WebSphere / Liberty

bash 
# status do servidor Liberty
${WLP_HOME}/bin/server status defaultServer

# iniciar / parar
${WLP_HOME}/bin/server start defaultServer
${WLP_HOME}/bin/server stop defaultServer

# logs em tempo real
tail -f ${WLP_HOME}/usr/servers/defaultServer/logs/messages.log
💡 Para thread dump em WebSphere tradicional: kill -3 <PID> — o dump é gerado no diretório de logs da instância.

Escalação de incidentes

1
Verificar monitoração (SiteScope / CDN)
Checar alertas no painel de monitoração. Confirmar se o problema é isolado a uma solução ou afeta múltiplos servidores.
2
Analisar logs da aplicação e do servidor
Verificar error_log (Apache), messages.log (Liberty) ou SystemOut.log (WebSphere). Buscar stack traces ou erros de conexão.
3
Acionar equipe responsável pela solução
Identificar a solução afetada no inventário e notificar a equipe de negócio. Registrar ocorrência no sistema de chamados.
4
Escalar para N2 se necessário
Se o problema não for resolvido em 30 min, escalar conforme matriz de responsabilidade. Acionar gestor via Teams.
